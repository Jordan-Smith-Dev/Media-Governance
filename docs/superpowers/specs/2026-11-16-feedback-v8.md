# Feedback v8 (agreed 2026-11-16)

Supersedes the Phase 1 design where they differ. The package is not in use yet, so no data is migrated.

## 1. People and consent
- Consent belongs to the **person**, not the image. It is a single yes/no on the person ("consent given"), set with a checkbox.
- Nothing else is captured: no permitted uses, given-on date, expiry, evidence form or "what this consent covers" note (per Matt).
- Every change (given, withdrawn) is written to the audit trail with who and when. This is the history.
- A person's page lists every image they are tagged in.
- Editing a person opens a slide-out panel.
- Consent options are removed from Settings.

## 2. Image view
- Remove the Compliance section.
- "Custom expiry" becomes "Expiry", prefilled with the calculated date.
- An indicator next to Expiry once the date has passed.
- Each tagged person is coloured by consent (green given, red not given).

## 3. Evidence storage
- Dropped: with consent reduced to yes/no there is no evidence to store.

## 4. Dashboard header and navigation
- Keep "Governance" in the Media sidebar; Umbraco's Media dashboard is unchanged.
- Clicking "Governance" opens our dashboard on its own page, not as a second tab beside Media's dashboard.
- Restyle the header strip like the Log Viewer's: a single bold "Governance" title (no "Media" link, no underline), thin vertical dividers between tabs, wider padded tabs with the icon above the label, pink bar under the active tab, our own icons.
- Not in scope: no overview section, filters or search, and no change to tab contents.

## 5. Access control
- Restrict access to user groups set in **appsettings only** (no picker).
- If none are configured, default to the *Sensitive data* group.

## 6. Settings
- Appsettings is the starting point for every setting.
- Editable in the CMS: notification recipients (emails and user groups), retention period, warning window (the last two override appsettings).
- Everything else is read-only in the CMS.
- Hide the media-tree toggles for launch (they stay on).
- Warn next to retention that changing it only affects new images (see 7).
- Reword "Recipients": the default is none, so nothing is sent; if no addresses but a group is listed, that group's members get the digest.

## 7. Added in v8
- Audit setting changes with the old and the new value.
- Shortening retention is a GDPR risk if existing images keep the longer period. Open question for the team: should a retention change also update existing images?
